🚀 Project Master Context
AI-Powered Product Intelligence, Compliance & Sustainability Platform

Purpose of this document:
This is the master context for the entire project. Every team member should provide this context to an AI assistant before asking it to design, generate, debug, or improve project code.

The AI must respect the architecture, ownership boundaries, interfaces, and rules defined here.

1. 🎯 Project Vision

We are building an AI-powered product inspection and intelligence platform.

The user takes or uploads an image of a packaged product.

The system analyzes the product and provides:

🔎 Product information
📝 OCR / label information
🍎 Nutritional / health-oriented analysis
⚖️ Regulatory compliance analysis
♻️ Packaging sustainability information
🗑️ Disposal / waste guidance
📍 Nearby disposal / collection locations
📊 Evidence and explanations

The system should transform:

PRODUCT IMAGE
      ↓
VISUAL INFORMATION
      ↓
TEXT / OCR
      ↓
STRUCTURED PRODUCT INFORMATION
      ↓
┌─────────────────┬─────────────────┬─────────────────┐
│                 │                 │                 │
│  COMPLIANCE     │    NUTRITION    │ SUSTAINABILITY  │
│                 │                 │                 │
└─────────────────┴─────────────────┴─────────────────┘
      ↓                 ↓                  ↓
                 INTELLIGENCE
                    RESULT
                       ↓
                    USER

2. 🧠 Core Product Idea

The system should follow this principle:

Scan → Understand → Evaluate → Explain → Act

Scan

The user uploads a product/package image.

Understand

The system extracts:

Product name
Brand
Ingredients
Nutrition information
MRP
Net quantity
Manufacturing date
Expiry / best-before
Manufacturer
Consumer information
Packaging/material information
Other relevant declarations
Evaluate

The system evaluates:

Regulatory compliance
Nutritional profile
Packaging sustainability
Disposal requirements
Explain

The system should show why something was detected.

Act

The system can tell the user:

What the issue is
What evidence supports it
What they can do
Where appropriate disposal/collection facilities may be located

7. 🤖 LLM / AI Usage

An LLM may be used for information extraction and explanation.

An LLM should NOT blindly make the final compliance decision.

Example:

OCR:

"M.R.P Rs 149
Net Qty 500g
Mfd: 06/2026
Sugar 28g"


LLM / NLP:

{
  "mrp": {
    "value": 149,
    "confidence": 0.97
  },
  "net_quantity": {
    "value": 500,
    "unit": "g",
    "confidence": 0.95
  },
  "manufacturing_date": {
    "value": "2026-06",
    "confidence": 0.93
  },
  "sugar": {
    "value": 28,
    "unit": "g",
    "confidence": 0.96
  }
}


The backend validates this output using Pydantic.

        ↓

        ↓

        ↓

        ↓

        ↓

Example:

  "rule_id": "LM_NET_001",
  "name": "Net Quantity Declaration",
  "field": "net_quantity",
  "required": true,
  "severity": "HIGH"
}


If:

net_quantity = missing


then:

Compliance = FAIL
Violation = Net quantity declaration missing
Severity = HIGH


The system should be able to show evidence for the decision.

21. 📦 Common Data Contracts

Pydantic should be used to establish contracts between services.

Example:

class OCRRegion(BaseModel):
    text: str
    confidence: float
    bbox: list[int]

class OCRResult(BaseModel):
    image_id: str
    regions: list[OCRRegion]


Example extracted field:

class ExtractedField(BaseModel):
    value: str | float | None
    confidence: float


Example violation:

class ComplianceViolation(BaseModel):
    rule_id: str
    severity: str
    message: str
    evidence: list[str]


These contracts prevent different team members from creating incompatible data formats.

23. 🔄 Backend Orchestration

Member 1's central responsibility is orchestration.

Conceptually:

ocr = await vision_service.process(image)

product_data = await nlp_service.extract(ocr)

nutrition = await nutrition_service.analyze(product_data)

compliance = await compliance_service.check(product_data)

sustainability = await sustainability_service.analyze(
    product_data
)

disposal = await disposal_service.recommend(
    sustainability
)

result = await database.save(
    ocr=ocr,
    product=product_data,
    nutrition=nutrition,
    compliance=compliance,
    sustainability=sustainability,
    disposal=disposal
)

return result


The exact implementation can differ.

The architectural principle should remain.

31. 🧠 AI vs Deterministic Logic

This distinction is extremely important.

AI / ML should handle
OCR where applicable
Information extraction
Entity recognition
Product classification
Ingredient interpretation
Unstructured text understanding
Human-readable explanations
Summarization
Deterministic logic should handle
Regulatory rules
Required fields
Rule matching
Compliance status
Severity
Nutrition scoring criteria
Disposal rules where known
Database operations
Authentication
Permissions
Principle

Use AI where interpretation is required. Use deterministic logic where correctness and repeatability are required.

37. 👨‍💻 AI Instructions for This Project

When any team member gives this document to an AI, the AI should follow these rules:

Respect the existing architecture.
Do not move responsibilities between team members without explaining why.
Do not replace deterministic compliance rules with an LLM.
Do not assume Groq is the OCR engine.
Use structured outputs between services.
Prefer Pydantic models for backend contracts.
Keep APIs simple and versioned.
Do not put the entire backend in one file.
Do not introduce unnecessary technologies.
Do not invent regulatory requirements.
Do not invent environmental facts.
Do not make medical claims from nutrition data.
Explain generated code when requested.
Generate production-conscious code, not blindly generated boilerplate.
Preserve existing interfaces unless there is a strong reason to change them.
When modifying code, consider how the change affects other team members.
Prefer small, testable components.
Include error handling for external APIs.
Never hardcode API keys or secrets.
If requirements are ambiguous, ask for clarification instead of inventing architecture.
